# Decisions log

Ambiguities resolved during the autonomous build. Newest last.

| # | Decision | Why |
|---|---|---|
| 1 | Build in the existing public repo `amankaushik481/openphotoai` instead of creating `openshoot`. | The build session is scoped to this repo (and can only create private repos). It is public, MIT, and the product is still branded "OpenShoot" via `NEXT_PUBLIC_APP_NAME`. |
| 2 | Single Next.js app (no monorepo). | Simplest for self-hosters: one `package.json`, one Docker image, one Vercel project. |
| 3 | Next.js 16.4 **without** Cache Components (`cacheComponents` off). | The app is mostly per-user dynamic UI; classic static/dynamic rendering avoids Suspense/`use cache` pitfalls. Marketing pages remain statically rendered. |
| 4 | Next 16 `proxy.ts` (formerly middleware) only does optimistic cookie checks; real auth happens in `route()` / `requireUserPage()`. | Next docs: proxy is not an authorization layer. |
| 5 | Postgres via Drizzle with `casing: "snake_case"`; text columns + TS unions instead of pg enums. | Adding enum values needs no migration. |
| 6 | `DATABASE_URL=pglite:./.data/pglite` supported (embedded Postgres) and used by unit tests (`pglite:memory`). | Zero-setup `pnpm dev`, hermetic fast tests; production uses real Postgres (Neon/Supabase/Docker). |
| 7 | shadcn/ui components are hand-written in `src/components/ui` (same API/style). | The shadcn registry host is blocked from the build environment; the components are plain source anyway. |
| 8 | Uploads are multipart POSTs to our API after **client-side resize to ≤2048px JPEG**, not presigned direct uploads. | One code path for local + S3, server runs safety/quality checks synchronously, EXIF/GPS stripped server-side, stays under Vercel's 4.5 MB body limit. |
| 9 | One `POST /api/jobs` endpoint with a Zod discriminated union (`type`) and one handler file per job type. | Uniform credits, rate limits, safety and refunds; parallel workstreams own one file each; the public API mirrors it. |
| 10 | Jobs: provider webhooks + lazy sync on `GET /api/jobs/:id` + `/api/cron/jobs` (Vercel cron) + `pnpm worker` (Docker). | No Redis/queue service; works on localhost (no public webhook URL) and serverless. |
| 11 | Edits/upscale/video/try-on only operate on media **generated by OpenShoot for the same user**; uploads are only accepted as pose references, garments and masks. | Prevents using the editor as a deepfake tool on arbitrary photos of other people. |
| 12 | Safety providers: `FACE_PROVIDER` (`local` = @vladmandic/human in-process, `rekognition` optional) and `MODERATION_PROVIDER` (`local` = nsfwjs + rule-based text filter, `openai` optional). Env validation **rejects mock safety when a real AI provider is configured**. Generation endpoints always set the provider safety checker on. | Safety must be the default and not switchable off; local models need no keys. |
| 13 | Stripe Checkout with inline `price_data` built from `src/config/plans.ts`; optional `STRIPE_PRICE_*` env pins. | Self-hosters don't need to create products/prices in the Stripe dashboard. |
| 14 | `pnpm setup` is a built-in pnpm command, so the bootstrap script is `pnpm run setup` (alias `pnpm bootstrap`). | Avoid the name clash. |
| 15 | Two identity modes: **Instant** (reference-based, free, seconds) and **Trained** (LoRA, best likeness). Stored in `identity_models.metadata.mode`. | Research: competitors moved to few-selfie instant flows; we offer both. |
| 16 | AI-generated labeling via IPTC `DigitalSourceType=trainedAlgorithmicMedia` XMP on every output (+ PNG text chunk); full signed C2PA manifests are optional future work (need a signing certificate). | Works everywhere without certificates; recognized by major platforms. |
| 17 | Packs are JSON files read at runtime by `src/server/packs/registry.ts` (bundled via `outputFileTracingIncludes`); `pnpm db:seed` validates them. No DB table. | Adding a pack = adding a file. |
| 18 | Work is committed on `main` (as requested) and mirrored to the session branch `claude/openshoot-saas-build-hckcls`. | The build harness requires the session branch; the user asked for everything on `main`. |
| 19 | Default models (fal): train `fal-ai/flux-lora-fast-training`, generate/draft `fal-ai/flux-lora`, multi-reference edit `fal-ai/nano-banana-2/edit`, inpaint `fal-ai/flux-lora/inpainting`, upscale `clarityai/crystal-upscaler`, face restore `fal-ai/codeformer`, bg removal `fal-ai/birefnet/v2`, video `fal-ai/kling-video/v3/standard/image-to-video`, TTS `fal-ai/minimax/speech-2.8-turbo`, talking video `fal-ai/kling-video/ai-avatar/v2/standard`, try-on `fal-ai/fashn/tryon/v1.6`, LLM `openrouter/router`, NSFW `fal-ai/x-ailab/nsfw`. | docs/MODELS.md research (2026-11-24). FLUX.1 LoRA kept over FLUX 3 Klein until likeness is A/B tested. |
| 20 | Drafts: 0 credits but capped (30/day for paying users, 5/day before first purchase). Instant-mode generation costs 2× credits; 4× upscale costs 5 credits. | FLUX.1 drafts are faster, not cheaper, at fal (per-MP billing rounds up); multi-reference edit costs ~2× a LoRA generation; 4× upscale is ~16 MP. Keeps every action margin-positive. |
| 21 | Replicate try-on uses `google/nano-banana-2` instead of `cuuupid/idm-vton`. | IDM-VTON is non-commercial licensed. |
| 22 | Docker Compose uses the pinned `pgsty/minio` community fork for local S3. | Upstream MinIO images were removed from Docker Hub. |
| 23 | S3 split-horizon in Compose solved with a loopback forwarder (`docker/loopback-forward.mjs`) so presigned `http://localhost:9000` URLs work from both the browser and the containers. | No extra env var; one code path. |
| 24 | User media is rendered with plain `<img>` (or `unoptimized`), not the Next image optimizer. | Signed URLs are private + short-lived; the optimizer would cache them and can't reach local MinIO. |
| 25 | Magic links land on `/verify`; the token is consumed only when the user clicks "Sign in". | Corporate link scanners otherwise burn one-time tokens. |
| 26 | Local face matching (human, cosine ≥ 0.60) is a **consistency check, not identity proof**: on sample data it rejected 31% of same-person pairs and had no false accepts, but two look-alike people scored 0.64–0.71. Operators who need stronger guarantees should use `FACE_PROVIDER=rekognition` (hybrid with CompareFaces). Documented in docs/SAFETY.md + KNOWN_ISSUES. | Honest about model limits; strict threshold favors safety. |
| 27 | Talking videos are refused for Together (multi-person) photos and edits derived from them. | The other person consented to photos, not to being made to speak. Photo-to-video stays allowed. *(Superseded by the safety review's SAF-12: photo-to-video now refuses Together photos too; see docs/SAFETY.md §2.)* |
| 28 | A team owner occupies one seat; admins can invite/remove members; only the owner renames, transfers credits or removes admins; max 20 brand kits per team. | Simple, predictable permissions. |
| 29 | Photos other users created with a deleted user's *shared* model stay in those users' galleries; the model, its training data and provider weights are deleted. | The photos belong to the requester's account; the consent record is deleted with the account. |
| 30 | Multi-person: invites expire after 14 days; an **accepted** share lasts 365 days (revocable anytime by either party); at least one model in a together photo must be the requester's own; likeness scoring is skipped for two-person photos. | Consent should not silently lapse after two weeks, but also should not be indefinite. |
| 31 | Share-link tokens are stored in plaintext (unlike invite/deletion tokens, which are hashed). | Share links are deliberately re-copyable bearer links (like file-sharing apps); they are revocable, optionally expiring and disabled on suspension or media removal. |
| 32 | Videos are labeled with MP4 `comment` / `description` tags naming the IPTC `trainedAlgorithmicMedia` source type + job id (stream copy, no quality loss); free-tier videos get the image watermark pill burned in (PNG overlay, re-encoded H.264 CRF 23). | Containers have no portable XMP slot that ffmpeg writes; tags survive most players/editors and keep parity with images. |
| 33 | Batch `Idempotency-Key` is stored on the batch's child jobs (`<key>:0`, `<key>:1`, …); job 0 is created first and alone so a concurrent replay hands over to the first batch. | No schema change (the batches table has no key column); reuses the jobs' unique (userId, idempotencyKey) index. |
| 34 | Completion errors flagged `retryable: false` (or non-transient `AppError`s) fail + refund the job at once instead of 3 completion attempts. | Bad provider output doesn't change on retry; users get their credits back immediately. |
| 32b | Docker verification in the build sandbox used a throwaway override (base image trusting the sandbox egress-proxy CA; fonts copied instead of `apt-get`, because deb.debian.org is blocked there). The committed Dockerfile is unchanged and is built normally by CI / users. | Sandbox network policy, not an app issue. |
