# Decisions log

Ambiguities resolved during the autonomous build. Newest last.

| # | Decision | Why |
|---|---|---|
| 1 | Build in the existing public repo `amankaushik481/openphotoai` instead of creating `openshoot`. | The build session is scoped to this repo (and can only create private repos). It is public, MIT, and the product is still branded "OpenShoot" via `NEXT_PUBLIC_APP_NAME`. |
| 2 | Single Next.js app (no monorepo). | Simplest for self-hosters: one `package.json`, one Docker image, one Vercel project. |
| 3 | Next.js 16.4 **without** Cache Components (`cacheComponents` off). | The app is mostly per-user dynamic UI; classic static/dynamic rendering avoids Suspense/`use cache` pitfalls. Marketing pages remain statically rendered. |
| 4 | Next 16 `proxy.ts` (formerly middleware) only does optimistic cookie checks; real auth happens in `route()` / `requireUserPage()`. | Next docs: proxy is not an authorization layer. |
| 5 | Postgres via Drizzle with `casing: "snake_case"`; text columns + TS unions instead of pg enums. | Adding enum values needs no migration. |
| 6 | `DATABASE_URL=pglite:./.data/pglite` supported (embedded Postgres) and used by unit tests (`pglite:memory`). | Zero-setup `pnpm dev`, hermetic fast tests; production uses real Postgres (Neon/Supabase/Docker). |
| 7 | shadcn/ui components are hand-written in `src/components/ui` (same API/style). | The shadcn registry host is blocked from the build environment; the components are plain source anyway. |
| 8 | Uploads are multipart POSTs to our API after **client-side resize to ≤2048px JPEG**, not presigned direct uploads. | One code path for local + S3, server runs safety/quality checks synchronously, EXIF/GPS stripped server-side, stays under Vercel's 4.5 MB body limit. |
| 9 | One `POST /api/jobs` endpoint with a Zod discriminated union (`type`) and one handler file per job type. | Uniform credits, rate limits, safety and refunds; parallel workstreams own one file each; the public API mirrors it. |
| 10 | Jobs: provider webhooks + lazy sync on `GET /api/jobs/:id` + `/api/cron/jobs` (Vercel cron) + `pnpm worker` (Docker). | No Redis/queue service; works on localhost (no public webhook URL) and serverless. |
| 11 | Edits/upscale/video/try-on only operate on media **generated by OpenShoot for the same user**; uploads are only accepted as pose references, garments and masks. | Prevents using the editor as a deepfake tool on arbitrary photos of other people. |
| 12 | Safety providers: `FACE_PROVIDER` (`local` = @vladmandic/human in-process, `rekognition` optional) and `MODERATION_PROVIDER` (`local` = nsfwjs + rule-based text filter, `openai` optional). Env validation **rejects mock safety when a real AI provider is configured**. Generation endpoints always set the provider safety checker on. | Safety must be the default and not switchable off; local models need no keys. |
| 13 | Stripe Checkout with inline `price_data` built from `src/config/plans.ts`; optional `STRIPE_PRICE_*` env pins. | Self-hosters don't need to create products/prices in the Stripe dashboard. |
| 14 | `pnpm setup` is a built-in pnpm command, so the bootstrap script is `pnpm run setup` (alias `pnpm bootstrap`). | Avoid the name clash. |
| 15 | Two identity modes: **Instant** (reference-based, free, seconds) and **Trained** (LoRA, best likeness). Stored in `identity_models.metadata.mode`. | Research: competitors moved to few-selfie instant flows; we offer both. |
| 16 | AI-generated labeling via IPTC `DigitalSourceType=trainedAlgorithmicMedia` XMP on every output (+ PNG text chunk); full signed C2PA manifests are optional future work (need a signing certificate). | Works everywhere without certificates; recognized by major platforms. |
| 17 | Packs are JSON files read at runtime by `src/server/packs/registry.ts` (bundled via `outputFileTracingIncludes`); `pnpm db:seed` validates them. No DB table. | Adding a pack = adding a file. |
| 18 | Work is committed on `main` (as requested) and mirrored to the session branch `claude/openshoot-saas-build-hckcls`. | The build harness requires the session branch; the user asked for everything on `main`. |
