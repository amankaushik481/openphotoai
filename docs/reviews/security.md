# Security review: OpenShoot

Independent review, report only. Scope: every route under `src/app/api/**`, the pages that mutate data or carry
tokens (`/verify`, `/s/[token]`, `/invites/[token]`, `/teams/join/[token]`, `/account/delete/confirm`,
`/dev/emails`, `/billing/mock-checkout`), `src/server/http.ts`, `src/server/auth/*`, `src/proxy.ts`, providers
(webhooks, storage, fetchOutput), `next.config.ts`, `src/lib/env.ts`, Docker and compose files.
There are no server actions (`"use server"` appears nowhere).

Findings were confirmed by reading each code path end to end. Where marked **(probed)**, a throwaway Vitest probe
was also run against the real code (PGlite and real Better Auth, no mocks of the code under test). The probes are in
`/tmp/claude-0/probes/*.probe.ts`. Run them with
`pnpm exec vitest run --config /tmp/claude-0/probes/vitest.probe.config.ts`.

**Counts:** 0 critical · 2 high · 4 medium · 12 low

## Verified OK

**AuthN/AuthZ**
- All 81 route files were reviewed. Every admin route uses `auth:"admin"` and every admin page calls `requireAdminPage()` itself, not only the layout. Every `/app/**` page calls `requireUserPage()`. `route()` rejects banned users for both session and API-key callers.
- Fresh user rows are loaded per request, so role, ban and deletion state are never taken from the cookie cache. `admitSignIn` blocks banned and deleted users at session creation. Admins cannot suspend themselves or other admins.
- **IDOR:** every query on user data is filtered by owner.
  - Jobs and batches use `getJobForUser`, `getBatchForUser`, `listJobsForUser` (`?ids` scoped), `cancelJob`, and the batch/job joins.
  - Media uses `getOwnedMedia`, `getOwnedMediaMany` (all-or-nothing), bulk actions, PATCH folder ownership, and the gallery viewer's neighbors, parent and children.
  - Folders, shares, API keys, training photos, consent and `getViewableModel` are all scoped. Team access goes through `getTeamFor{Member,Manager,Owner}` (non-members get 404). Brand kits use `getManagedKit` and `getUsableBrandKit`.
  - Multi-person: `findInvite` by share id is limited to the invitee or owner, `assertModelsUsable` requires an accepted, unexpired share from the current owner, and `revokeShare` requires either party.
  - Every job handler's `plan()` re-authorizes the ids it references, with upload purpose enforced (reference, garment, mask).
- **Mass assignment:** request schemas are strict or strip unknown keys, and job inputs are stored as parsed. Better Auth additional fields (`role`, `credits`, `plan`, `hasPaid`, `banned`, …) are `input:false` (probed: 400). `prepareNewUser` derives `role` only from `ADMIN_EMAILS`. The credit ledger locks the user row and never lets a balance go negative. Credit transfers are owner-only, go to active members only, and run in one transaction.

**Webhooks**
- fal: Ed25519 over the raw body, JWKS cached with a forced refresh at most once per minute, ±5 min skew, and a signed request id that must match the body. The `X-Fal-Webhook-User-Id` header is not pinned to our account, but jobs are looked up by `provider + providerRequestId`, so a foreign fal account's webhook is a no-op.
- Replicate: Standard Webhooks HMAC with `timingSafeEqual`, ±5 min, and it fails closed without a secret. Stripe uses `constructEventAsync` on the raw text (default 300 s tolerance). Mock webhooks use an HMAC with a purpose-bound key.
- Signatures are always verified before JSON parsing. Payment routes return 404 unless the provider in the path is the configured one, and an unconfigured AI provider fails verification (401).
- Idempotency comes from the `webhook_events` (source, eventId) claim, with re-claim only for failed or stale rows, plus ledger idempotency keys.

**Secrets and tokens**
- API keys, team and multi-person invite tokens, deletion tokens and consent capture tokens are stored as SHA-256. Magic-link tokens use `storeToken:"hashed"`. All are 32-char random tokens from a 62-char alphabet (about 190 bits).
- Cron uses a constant-time compare (sha256 digests in `isCronAuthorized`). `/api/cron/jobs` is closed in production without `CRON_SECRET`, and `/api/cron/maintenance` is always closed without it.
- Local-file signatures use HMAC with a purpose-derived key and `timingSafeEqual`, with a maximum 7-day TTL. The email outbox redacts secret URLs for real deliveries.
- The account export excludes embeddings, key/token hashes, provider refs and storage keys. The Media, Job and Model DTOs expose no storage keys, provider refs, embeddings or costs.
- Signed URL lifetimes: 1 h for UI, 2 h for provider inputs, 24 h for export (documented), 7 days for share og (see SEC-14).

**Files**
- Image type is detected from magic bytes; SVG and HTML are never accepted. References, garments, selfies and training photos are re-encoded to JPEG with metadata stripped. Masks must be PNG and are decoded with a pixel cap.
- `limitInputPixels: 100M` and `failOn:"error"` are set on every untrusted decode path (`process.ts`, `image-decode.ts`, `inpaint.ts`). Provider outputs are re-encoded (labelled JPEG/PNG, MP4).
- Local storage: `assertSafeKey` rejects `..`, absolute paths, backslashes and control characters, `resolvePath` enforces the storage root, and the HMAC must match the exact key.
- `/api/files` sets Content-Type from an extension allowlist, `nosniff`, and `CSP: default-src 'none'; sandbox`. `Content-Disposition` is sanitized with RFC 6266.
- Zip downloads are capped at 200 ids and 30 per hour, stream one file at a time, use server-generated entry names (no zip-slip), and are checked for same origin on form posts.
- `fetchOutputBytes` allows https only, caps size at 100 MB (streamed), and times out after 120 s.

**CSRF, dev endpoints and redirects**
- Better Auth cookies are `HttpOnly`, `SameSite=Lax`, and `Secure` with an https base URL. Better Auth endpoints check origin (`trustedOrigins:[appUrl]`).
- `/api/dev/emails/latest`, `/dev/emails` and `/api/billing/mock/*` return 404 when not in mock mode (but see SEC-2). `/api/demo/*` does not exist. The dev-mail iframe uses `sandbox=""`.
- `safeNextPath` and `safeLoginPath` reject `//`, `\` and tab/newline tricks through a WHATWG origin check, and refuse to return to auth paths. The login, verify, proxy and `requireUserPage` redirects are all same-origin. Stripe success, cancel and portal URLs are server-built.

**Enumeration**
- Magic-link responses are identical for known and unknown emails. The report response never reveals whether content exists. Team ids answer 404 for non-members. Share, invite and deletion pages require a high-entropy token. The share token regex is checked before any DB lookup.

**Config**
- `poweredByHeader:false`. Env is validated with Zod, lazily, and the build phase is exempt. The AI safety invariant (real AI requires non-mock face and moderation providers) cannot be overridden. `DEMO_MODE` requires mock AI and payments. MinIO is bound to `127.0.0.1` in compose and the bucket is private. Docker runs as the non-root `node` user.
