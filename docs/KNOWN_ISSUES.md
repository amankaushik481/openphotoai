# Known issues

Deliberately deferred findings from the reviews in `docs/reviews/`, with the reason and the mitigation in place.

## Security

Fixed from `docs/reviews/security.md`: SEC-1 to SEC-9, SEC-11, SEC-13, SEC-17 and SEC-18 in full. SEC-10, SEC-12,
SEC-14 and SEC-15 are fixed in part (the remainder is listed below). SEC-16 is deferred.

| ID | What remains | Why deferred | Mitigation in place |
|---|---|---|---|
| SEC-16 | Share-link tokens are stored in plaintext (`share_links.token`). Storage keys contain `users/{userId}/`, which shows up in signed URLs on public share pages. | Hashing needs a schema change and a migration. The share dialog also lets owners copy existing links again, which needs the plaintext token (or an encrypted copy in a new column). Opaque storage prefixes mean moving every stored object. `src/db/schema.ts` belongs to another workstream. | Tokens are about 190-bit random values. A leaked user id is no longer enough to forge sessions (SEC-1), because production refuses weak or published `BETTER_AUTH_SECRET` values. |
| SEC-10 | The CSP is a baseline only (`base-uri 'self'; object-src 'none'; frame-ancestors 'self'`). It has no `script-src` / `img-src` / `connect-src`. | A nonce-based `script-src` makes every page dynamic, which loses static marketing pages and hurts Lighthouse. `img-src` / `connect-src` depend on the runtime `S3_ENDPOINT`, which isn't known when `next.config.ts` headers are built (Docker builds once, then runs anywhere). | React escapes all user content. There are no `dangerouslySetInnerHTML` sinks with user data. The other security headers are set. HSTS is sent when `NEXT_PUBLIC_APP_URL` is https. |
| SEC-12 | `parseBody` still accepts any `Content-Type` (for example `text/plain`). | Requiring `application/json` would break existing API clients that omit the header. It isn't needed for CSRF anymore. | `route()` refuses cookie-authenticated writes whose `Sec-Fetch-Site` isn't `same-origin` or whose `Origin` is foreign (this also covers same-site sibling origins such as MinIO on `localhost:9000`). `SameSite=Lax` still applies. |
| SEC-14 | After sign-out-everywhere, a stolen session cookie keeps working for up to 5 minutes through Better Auth's `cookieCache`. Signed page URLs on a revoked share stay valid for up to 1 hour. | The cookie cache avoids a session DB read on every request. Bans and deletions are already re-checked on every request (`loadUser`). | The share `og:image` URL now lives 1 h instead of 7 days. |
| SEC-15 | `fetchOutputBytes` checks every redirect hop for https and a public IP *literal*. It does not resolve hostnames, so a name that resolves to a private address would still be fetched. | Exploiting this needs a compromised AI provider, because output URLs only come from signed webhooks or authenticated provider APIs. DNS checks have rebinding races unless the connection is pinned. | Redirects are followed manually, at most 3, and each must be https. Internal names (`localhost`, `*.internal`, `*.local`) are refused. Size and time limits apply. |
| SEC-4 | With `TRUSTED_PROXY_HOPS=0` (the default outside Vercel), the client IP is unknown. Per-IP limits (reports, deletion-confirm attempts, Better Auth's own limiter) then share one bucket for all visitors. Team and multi-person invites are limited per inviter (30/h), not per recipient. | Without a trusted proxy, an app has no trustworthy client IP: Next.js only fills `X-Forwarded-For` when the client didn't send one. Failing closed (shared bucket) is safer than trusting a spoofable header. | `.env.example`, `docs/SELF_HOSTING.md` and `pnpm check-env` explain `TRUSTED_PROXY_HOPS`. Production logs a one-time warning when requests arrive through a proxy while it is 0. Magic links also have a per-recipient limit (5/h), and anonymous reports no longer send email, so neither depends on the IP. Consent records keep the raw forwarded chain next to the resolved IP. |
| SEC-11 | A magic link isn't bound to the browser that requested it. | Binding it needs a cookie set at request time plus cross-device handling ("open the link on your phone"). | `/verify` shows the email address the link signs into, and warns the user not to continue if it isn't theirs. |
| SEC-6 | Next.js `serverActions.bodySizeLimit` is still 10 MB. Bodies below the route caps are buffered in memory (1 MB JSON, 4 MB webhooks, 8 MB + 64 KB uploads, 64 KB auth). | There are no server actions. The per-route caps bound memory per request. | For self-hosting, also set a body limit on the reverse proxy (for example nginx `client_max_body_size 10m`), as described in `docs/SELF_HOSTING.md`. |
| SEC-1 | Docker deployments that relied on the old public compose secret are signed out once, because the entrypoint now generates a random secret and stores it in the `app-data` volume. | This is intended: the old value let anyone forge sessions. | To rotate the secret, delete `/data/.auth-secret` (or the volume), or set `BETTER_AUTH_SECRET` explicitly. |

## Payments & credits

Fixed from `docs/reviews/payments.md`: PAY-1, PAY-3, PAY-5, PAY-7, PAY-10, PAY-11, PAY-12, PAY-15 and PAY-18 in full;
PAY-2, PAY-6, PAY-8 and PAY-9 in part (the remainder is listed below). PAY-4's root cause is fixed in `src/lib/env.ts`
(production refuses real AI with mock payments or email); billing also ignores subscriptions of a provider that isn't
configured. PAY-13, PAY-14, PAY-16, PAY-17 and PAY-19 are deferred.

Stripe webhook events the endpoint must be subscribed to (`STRIPE_WEBHOOK_EVENTS` in `src/providers/payment/stripe.ts`):
`checkout.session.completed`, `checkout.session.async_payment_succeeded`, `customer.subscription.created`,
`customer.subscription.updated`, `customer.subscription.deleted`, `invoice.paid`, `invoice.payment_failed`,
`charge.refunded`, `charge.dispute.created`, `charge.dispute.closed` (`charge.dispute.funds_withdrawn` is optional).

Policies these fixes introduce: a full refund of a subscription invoice ends that subscription (refund partially to
keep it); a dispute reverses every credit the payment granted (the balance may go negative), ends its subscription and
writes a `payment_disputed` moderation event; a won dispute (or an inquiry closed without a chargeback) restores the
credits but not the subscription; a negative balance blocks all jobs, free drafts included; a refunded low-likeness
photo is discarded instead of hidden; invoices with a zero total (trials, 100% coupons) start the plan without credits.

| ID | What remains | Why deferred | Mitigation in place |
|---|---|---|---|
| PAY-9 | Credits a team owner transferred to a member are not clawed back when the owner's purchase is later refunded or charged back. | Clawing back from a member who already spent the credits needs a debt model (or holding recently bought credits), which is a product decision. | The owner's balance goes negative, which blocks the owner's jobs, drafts and further transfers. A chargeback flags the owner in the moderation queue; an admin can adjust the member's balance. Transfers take an `Idempotency-Key` and are limited to 60 per hour. |
| PAY-6 | Upgrades made outside our checkout (Customer Portal plan switching, dashboard edits) aren't topped up for the rest of the current period: Stripe bills a `subscription_update` proration invoice, which grants no credits. For inline (non-pinned) prices changed in the dashboard, webhooks carry no product metadata, so the plan still comes from subscription metadata. | Granting the prorated difference needs per-period accounting; portal switching is not part of the app's flow. | The billed price now wins over subscription metadata (pinned `STRIPE_PRICE_*`, price and product metadata), so later cycles grant the right plan's credits. `SELF_HOSTING.md` and `.env.example` say to keep portal plan switching off. |
| PAY-2 | Only fal reports the TTS audio duration, so only fal refuses over-long speech before the per-second avatar step. Replicate relies on the script estimate alone. The character rates are heuristics (CJK 5/s, digits 3/s, other characters 15/s). | Replicate's TTS output is a bare URL; probing the audio would mean downloading and decoding it. | The estimate takes the larger of words and characters, so scripts without spaces are priced and capped (60 s) by their length; the cap is enforced on the server with the same function the editor uses. |
| PAY-8 | Instant-model drafts (which run on the pricier multi-reference model) aren't charged or counted separately. | Charging drafts changes the free tier; a separate allowance needs product input. | The daily allowance now counts images (5 for never-paid users, 30 otherwise), so a free account gets at most 5 instant draft images a day instead of 20. |
| PAY-3 | If the previous subscription had any provider event newer than the new checkout (e.g. it renewed in the same seconds), it isn't canceled automatically and the user is billed for both. | Telling a racing renewal from a genuinely newer subscription needs the provider's creation time, which we don't store. | Both plans stay active (the best one applies), which support can fix; previously the newest plan could be canceled. |
| PAY-13 | Provider calls after commit (canceling superseded, refunded or disputed subscriptions) and receipt emails are not retried if they fail. | A durable outbox needs a new table (`src/db/schema.ts` belongs to another workstream). | Failures are logged. Refunds and disputes mark the subscription canceled locally in the transaction, so the plan drops even if the provider call fails. |
| PAY-14 | An in-app plan switch creates a new subscription and cancels the old one immediately, without proration. | Proper switching uses `subscriptions.update` with proration and a different checkout flow; that's a feature, not a fix. | Credits already granted are kept. |
| PAY-16 | `refund.failed` is ignored: credits reversed by `charge.refunded` are not restored when a refund fails. | We don't map refund ids to their ledger reversal (reversals are keyed by event). | Rare; an admin can re-grant with a credit adjustment. |
| PAY-17 | Admin revenue, MRR and margin add up amounts across currencies. | Settlement-currency amounts need a balance-transaction lookup per payment. | Inline prices are USD only, so this only affects pinned non-USD prices or Adaptive Pricing. |
| PAY-19 | Partial refunds (blocked / missing / likeness) written by a completion attempt that later lost its lease are kept under fixed tags. | Needs the refunds to move into the success transaction keyed by lease token. | Lease loss is rare and refunds stay capped at what was charged. |
| PAY-4 | A user's stored `plan` from leftover mock subscriptions is only recomputed at their next payment event after switching to Stripe. | A one-off migration is an operator task. | Production refuses real AI with mock payments; plan recomputation and the billing page ignore subscriptions of a provider that isn't configured. |
